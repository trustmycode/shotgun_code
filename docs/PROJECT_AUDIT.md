# Технический аудит `shotgun_code`

Дата актуализации: 17 июля 2026 года. Документ описывает состояние ветки подготовки к публичной публикации после устранения критических замечаний.

## Итог и оценки

`shotgun_code` — настольное приложение Wails для выбора локальных файлов, сборки контекста и отправки задачи в OpenAI, Google Gemini или OpenRouter. После исправлений проект имеет воспроизводимую проверку, первые тесты безопасности, ограниченные локальные файлы и прозрачное описание форка. Главные оставшиеся риски: ключи и история не шифруются, большая часть файловой логики не покрыта тестами, а общий объект `App` всё ещё сочетает несколько ответственностей.

| Область | Оценка |
|---|---:|
| Архитектура | 65/100 |
| Надёжность | 68/100 |
| Поддерживаемость | 62/100 |
| Тесты | 60/100 |
| Безопасность | 64/100 |
| Инфраструктура | 78/100 |
| Документация | 86/100 |
| **Средняя** | **69/100** |

Оценка безопасности не выше средней: ключи больше не возвращаются интерфейсу, но по-прежнему находятся в локальном JSON без шифрования ([`app.go`](../app.go#L39), [`llm_settings.go`](../llm_settings.go#L92)).

## Исправленные критические замечания

1. Интерфейс получает только признаки наличия ключей, а не их значения ([`llm_settings.go`](../llm_settings.go#L17), [`llm_settings.go`](../llm_settings.go#L92)); это проверяется тестом сериализации ([`llm_settings_test.go`](../llm_settings_test.go#L35)).
2. Настройки и история записываются через временный файл, синхронизацию и атомарное переименование с правами `0600`; каталог ограничен правами `0700` ([`secure_file.go`](../secure_file.go#L9), [`secure_file.go`](../secure_file.go#L17)).
3. История ограничена 50 записями и приблизительно 20 МБ, чтобы исключить бесконтрольный рост ([`history_manager.go`](../history_manager.go#L30), [`history_manager.go`](../history_manager.go#L47)).
4. Пользовательский базовый адрес принимает только HTTPS без встроенных реквизитов, запроса и фрагмента ([`llm_settings.go`](../llm_settings.go#L188)).
5. Вызовы OpenAI и OpenRouter имеют двухминутный срок ожидания и предел ответа 8 МБ ([`http_safety.go`](../internal/llm/provider/http_safety.go#L12)); тело ошибочного ответа больше не попадает в журнал ([`openai.go`](../internal/llm/provider/openai.go#L189), [`openrouter.go`](../internal/llm/provider/openrouter.go#L194)).
6. Добавлены `go test -race`, `go vet`, сборка Vue и полноценная сборка Wails для Linux на каждый запрос слияния ([`ci.yml`](../.github/workflows/ci.yml#L12), [`ci.yml`](../.github/workflows/ci.yml#L46)).
7. Удалён отслеживаемый исполняемый файл, а `.gitignore` исключает его повторное добавление ([`.gitignore`](../.gitignore#L10)).
8. Происхождение проекта явно обозначено как форк; авторские уведомления и лицензия правообладателя сохранены ([`NOTICE.md`](../NOTICE.md#L1), [`README.md`](../README.md#L7)).

## 1. Назначение и стек

Приложение превращает выбранные файлы проекта в структурированный текст, позволяет дополнить его задачей и отправить поставщику модели. Стек: Go 1.24, Wails 2.11, Vue 3, Vite 5, Tailwind CSS и langchaingo ([`README.md`](../README.md#L19), [`go.mod`](../go.mod#L1), [`frontend/package.json`](../frontend/package.json#L1)).

## 2. Точки входа и основные компоненты

- [`main.go`](../main.go#L1) запускает Wails и встраивает собранный интерфейс.
- [`app.go`](../app.go#L54) содержит состояние, обход файлов и координацию фоновой генерации.
- [`auto_context_service.go`](../auto_context_service.go#L58) строит запрос для автоматического выбора файлов и проверяет результат.
- [`internal/llm/provider/provider.go`](../internal/llm/provider/provider.go#L23) задаёт интерфейс поставщика и фабрику.
- [`history_manager.go`](../history_manager.go#L37) управляет локальной историей.
- [`frontend/src/components/MainLayout.vue`](../frontend/src/components/MainLayout.vue#L1) связывает основные экраны Vue.

## 3. Главный поток данных

Пользователь выбирает каталог, после чего приложение строит дерево с учётом `.gitignore` и своих правил ([`app.go`](../app.go#L145), [`app.go`](../app.go#L190)). Выбранные файлы читаются и включаются в блоки `<file>`, а общий результат ограничивается десятью мегабайтами ([`app.go`](../app.go#L25), [`app.go`](../app.go#L595)). Далее инструкция передаётся поставщику и результат сохраняется в ограниченной истории ([`history_manager.go`](../history_manager.go#L155), [`history_manager.go`](../history_manager.go#L179)).

## 4. Архитектурные границы

Сильные границы — интерфейс поставщиков, отдельный менеджер истории и мост Wails. Кэш поставщика защищён мьютексом ([`app.go`](../app.go#L66), [`llm_settings.go`](../llm_settings.go#L212)). Слабая граница — `App`: он хранит настройки, наблюдатель, правила, генератор, историю и кэш в одном объекте ([`app.go`](../app.go#L54)). Следующий разумный шаг — выделить файловый индекс, хранилище настроек и службу выполнения запросов.

## 5. Обработка ошибок

Ошибки возвращаются через Wails и журналируются; отмена и превышение размера имеют отдельные ветви ([`app.go`](../app.go#L320), [`app.go`](../app.go#L595)). Сетевые ответы вне диапазона 2xx не раскрывают тело в журнале и возвращают код состояния ([`openai.go`](../internal/llm/provider/openai.go#L187)). Повторов с задержкой и единой классификации временных ошибок пока нет.

## 6. Асинхронность, фоновые задачи и гонки

Новая генерация контекста отменяет предыдущую, а уникальный маркер не позволяет старой задаче очистить состояние новой ([`app.go`](../app.go#L271), [`app.go`](../app.go#L286)). История и кэш поставщика защищены отдельными мьютексами ([`history_manager.go`](../history_manager.go#L42), [`app.go`](../app.go#L67)). Остаётся риск конкурентного доступа к `settings`, правилам исключения и наблюдателю, потому что единой блокировки состояния `App` нет ([`app.go`](../app.go#L54)).

## 7. Транзакции и работа с базой

Базы данных нет. Настройки и история являются локальными JSON-файлами. Запись теперь атомарна на одном файловом разделе: временный файл синхронизируется и переименовывается ([`secure_file.go`](../secure_file.go#L30), [`secure_file.go`](../secure_file.go#L48)). Нет блокировки между двумя одновременно запущенными экземплярами приложения; последний писатель победит.

## 8. Безопасность и возможные секреты

В отслеживаемых файлах действующих ключей не обнаружено. Ключи не выходят в интерфейс после сохранения ([`llm_settings.go`](../llm_settings.go#L92)) и не включаются в диагностическое представление вызова ([`openai.go`](../internal/llm/provider/openai.go#L270)). Однако они остаются незашифрованными в `settings.json`; права `0600` уменьшают, но не устраняют риск компрометации профиля пользователя ([`SECURITY.md`](../SECURITY.md#L5)). Пользовательский HTTPS-адрес намеренно получает настоящий ключ и исходники, о чём интерфейс и документация предупреждают ([`LlmSettingsModal.vue`](../frontend/src/components/LlmSettingsModal.vue#L39), [`README.md`](../README.md#L56)).

## 9. Тесты и критичные непокрытые сценарии

Есть тесты атомарного файла и прав, безопасного представления ключей, проверки адреса, ограничения истории и сетевого ответа ([`secure_file_test.go`](../secure_file_test.go#L9), [`llm_settings_test.go`](../llm_settings_test.go#L9), [`history_manager_test.go`](../history_manager_test.go#L10), [`http_safety_test.go`](../internal/llm/provider/http_safety_test.go#L9)). Проверка выполняется с обнаружением гонок ([`ci.yml`](../.github/workflows/ci.yml#L40)).

Критически не покрыты: символические ссылки и циклы, правила исключения на разных ОС, отмена реальной фоновой задачи, наблюдатель файлов, два экземпляра приложения, сетевые формы ответов поставщиков и поведение интерфейса.

## 10. Производительность

Формируемый контекст ограничен 10 МБ ([`app.go`](../app.go#L25)); ответы OpenAI и OpenRouter — 8 МБ ([`http_safety.go`](../internal/llm/provider/http_safety.go#L12)); история — 20 МБ ([`history_manager.go`](../history_manager.go#L32)). Для Gemini действует двухминутный контекст, но отдельного предела тела на уровне используемой библиотеки нет. Тем не менее дерево и содержимое обходятся несколькими проходами, а история при каждом добавлении сериализуется целиком. Для очень больших монорепозиториев полезны потоковая сборка, единый проход и измерение времени по этапам.

## 11. Логи и наблюдаемость

Wails-события сообщают ход и завершение генерации, а время фоновой работы фиксируется в журнале ([`app.go`](../app.go#L297), [`app.go`](../app.go#L312)). Отладочная печать полных локальных путей удалена. Не хватает структурированных полей, счётчиков ошибок поставщиков и отдельного безопасного режима журнала.

## 12. Docker, CI/CD и воспроизводимость запуска

Docker для настольного приложения не нужен. Версии локального запуска, `go.mod`, обычной проверки и выпуска согласованы на Go 1.24, Node.js 22 и Wails 2.11 ([`README.md`](../README.md#L26), [`ci.yml`](../.github/workflows/ci.yml#L19), [`build.yml`](../.github/workflows/build.yml#L45)). `npm ci` использует файл блокировки ([`wails.json`](../wails.json#L5)). Ручной выпуск по-прежнему имеет право записи содержимого, но обычные запросы слияния выполняются только с правом чтения ([`build.yml`](../.github/workflows/build.yml#L3), [`ci.yml`](../.github/workflows/ci.yml#L8)).

## 13. Документация

README описывает запуск, архитектуру, передачу данных, проверки и ограничения лицензии ([`README.md`](../README.md#L26), [`README.md`](../README.md#L56), [`README.md`](../README.md#L90)). Отдельные документы фиксируют происхождение и порядок сообщения об уязвимости ([`NOTICE.md`](../NOTICE.md#L1), [`SECURITY.md`](../SECURITY.md#L1)). Старый архитектурный документ в `design/` местами отстаёт от текущего экрана истории и требует последующей актуализации.

## 14. Часть AI/LLM

Единый интерфейс поддерживает три поставщика ([`provider.go`](../internal/llm/provider/provider.go#L23)); для моделей семейства GPT-5 есть отдельные вызовы OpenAI Responses и OpenRouter Chat Completions ([`openai.go`](../internal/llm/provider/openai.go#L67), [`openrouter.go`](../internal/llm/provider/openrouter.go#L62)). Автоматический выбор принимает только существующие пути ([`auto_context_service.go`](../auto_context_service.go#L270)). Нет потоковой выдачи, бюджета стоимости, повторов, оценки качества выбора файлов и автоматического поиска секретов перед отправкой.

## 15. Риски публичной публикации

Происхождение форка теперь описано честно, но нестандартная лицензия остаётся блокирующим юридическим вопросом: она запрещает удалять уведомления, вводит предел выручки и ограничение конкурирующего продукта, при этом явное право публичного распространения сформулировано неочевидно ([`LICENSE.md`](../LICENSE.md#L1), [`LICENSE.md`](../LICENSE.md#L35)). До подтверждения правообладателя нельзя считать риск публичной публикации закрытым ([`NOTICE.md`](../NOTICE.md#L7)). Технические остаточные риски — незашифрованные локальные ключи/исходники, неполное покрытие файловой логики и возможные гонки общего состояния. Нельзя представлять исходный проект как полностью собственную разработку.
